2GitHub 구조 이해(Team * Repo 중심과 Organization 부재)

Enterprise의 위치 - 나중에 덧씌운 뚜껑

이승희는 GitHub의 뿌리부터 짚었다. Git은 오픈소스 협업에서 나왔고 사용자 묶음인 Team과 저장소인 Repo가 한 쌍을 이룬다. 여러 Team과 Repo를 관리할 정책이 필요해져 Organization이 생겼다. Enterprise는 기업 요구에 맞추려고 그 위에 나중에 씌운 뚜껑이며 Organization과 위계 관계가 아니다.

  • 정책의 자리. GitHub 정책 대부분은 Enterprise가 아니라 Organization에 있다.
  • HS AX추진팀의 구조. Copilot만 구매해 Organization이 없다. Organization을 만들면 추가 비용이 생기므로 만들지 않는다. 그래서 Enterprise가 모든 사용자에게 정책을 직접 적용하고 이런 사용자를 Enterprise Assigned User라고 부른다.
  • 위계가 아니라서 가능한 운영. Organization 없이도 Enterprise Teams로 사용자와 정책을 관리할 수 있다.
  • 런북 STEP 12. Organization * Team 생성은 1차 세션에 이어 이번에도 건너뛰었다.

Enterprise Teams와 보안그룹

GitHub에는 Organization Team과 Enterprise Team이 있다. Organization Team은 Organization 아래에서 만들고 Enterprise Team은 Enterprise가 직접 만든다. Team은 GitHub 관리자가 직접 만들거나 Entra 보안그룹과 매핑해서 만들 수 있다.

보안그룹을 Enterprise Team에 매핑하면 버짓 설정 * 사용자 추가/탈퇴 * Copilot 라이선스 할당 * 정책 설정까지 팀 단위로 할 수 있다. Entra의 엔터프라이즈 앱에는 사용자를 하나씩 할당하거나 보안그룹을 할당할 수 있다. 보안그룹을 할당하고 자동 프로비저닝을 켜면 그룹원이 모두 GitHub Member로 들어 올 수 있고. Owner는, 이미 했던 것처럼, 2명뿐이니 개별 사용자로 넣으면 된다.

6모델 정책(허용 목록과 Fusion)

허용 목록 방식의 운영

모델마다 크레딧 소모량과 성능이 달라 관리자가 정해야 한다. 이승희는 차단 목록(Blacklist)이 아니라 허용 목록(Whitelist)으로 운영하라고 권고했고 홍진섭 책임이 동의했다. 신규 모델을 무조건 열어 두면 한정된 크레딧을 하루 만에도 쓸 수도 있다.

Enterprise Teams 모드와 모델 선택

  1. Enterprise Teams 모드를 켠다. 모델 사용 권한은 원래 Organization이 쥐고 있었다. Organization이 없는 HS AX추진팀은 Enterprise Teams 기준으로 제어해야 한다. 모드를 켜면 선택지가 Disabled/ Enabled/ Delegate to organizations에서 Disabled/ Enabled/ Delegate to Enterprise Teams로 바뀐다.
    (Bug : 토글이 화면에서 되돌아가는 현상이 있어 새로고침한 뒤 On을 확인했다.)
  2. 신규 모델의 기본 노출은 Disabled로 둔다. 모델이 보이면 곧 쓸 수 있다. 비용과 성능을 모르는 모델을 기본으로 열지 않는다.
  3. Configure models에서 모델별 상태를 정한다. 홍진섭 책임이 HS AX추진팀이 이미 쓰는 환경의 VS Code 모델 목록을 기준으로 맞췄다. 이 화면에는 예전에 보이던 비용 배수가 표시되지 않는다.
  4. Custom model은 쓰지 않는다. 자체 모델을 가져오는 기능이다. 홍진섭 책임이 로컬 LLM인 EXAONE을 API Key로 붙일 수 있는지 물었고 이승희는 EXAONE 팀에 물어보는게 좋겠다고 했다. EXAONE은 아직 Azure에 올라와 있지 않다. 

Copilot Fusion과 Auto

Fusion은 작업에 맞춰 모델과 노력도(Standard/ High/ Max)를 스스로 고르는 방식이다. 이승희의 VS Code 1.146에는 Copilot Fusion이 30% 할인으로 보였다. HS AX추진팀의 VS Code 1.143에는 Auto가 10% 할인으로 보였다. 이승희는 VS Code를 최신 버전으로 올리면 Fusion이 보인다고 안내했다.

정책에는 Fusion이 고를 수 있는 모델 목록이 따로 있다. 이승희는 성능 대비 효율이 낮은 모델을 이 목록에서 뺄 수 있다고 설명했다. Fusion은 사용자가 모델을 의식하지 않고 쓰는 기능이라 중요한 작업에는 잘 쓰지 않는다는 이유다.

일부 모델은 Fusion에서 Max 노력도가 필요하다고 표시된다. 홍진섭 책임은 토큰이 많이 나가는 Max 고정 모델을 목록에서 뺐다. 예를 들어 Sonnet 일부 버전은 Max 고정이라 제외했고 Sonnet 5는 앞 단계의 모델 설정에서 다시 켜기로 했다. 뺀 모델의 정확한 목록은 확인 필요.

8클라우드 PC의 404 오류(브라우저 캐시 의심과 시크릿 모드 우회)

HS AX추진팀의 클라우드 PC 브라우저에서 SSO 주소가 404로 열렸고 로컬 PC에서는 정상으로 열렸다. 이승희가 원인을 가르는 순서를 안내했다.

  1. 로컬 PC와 클라우드 PC의 PowerShell에서 아래 명령을 실행해 응답 코드를 비교한다. 명령은 이승희가 회의 채팅에 남겼다.

    curl -v https://github.com/enterprises/<slug>/sso

    - Andrew (SungHee) Yi, 회의 채팅 (slug는 Enterprise 주소의 값으로 바꾼다)
  2. 클라우드 PC의 curl 결과는 200 OK였다. 네트워크 경로는 정상이다.
  3. 같은 클라우드 PC의 시크릿 모드 브라우저에서는 SSO 페이지가 열렸다.

이승희는 GitHub가 권한이 없는 접근도 404로 응답한다고 설명했다. 설정 오류가 아니므로 GitHub 엔지니어에게 물을 사안이 아니라고 판단했다. 원인은 클라우드 PC 브라우저의 캐시나 이전 접속 이력으로 봤다.

  • 홍진섭 책임이 클라우드 PC를 재부팅해 캐시를 정리한 뒤 다시 접속해 본다.
  • 계속 안 되면 시크릿 모드나 Edge로 접속한다.
