2Copilot Business 단독 계약과 Organization 생성 금지

진행 이승희 (Microsoft)

이승희가 런북 '1. 개요 및 배경'을 열고 GitHub Enterprise Cloud(GHEC)부터 짚었다. GHEC는 흔히 아는 GitHub, 곧 클라우드의 코드 저장소다.

HS AX팀이 계약한 것은 Copilot Business 하나다. HS AX팀은 GitHub를 저장소로 쓰지 않는다. 저장소까지 쓰면 Copilot과 별도로 저장소 비용을 이중으로 낸다.

Organization 생성 금지

엔터프라이즈 안에 Organization을 만들면 GHEC 저장소가 자동으로 붙고 저장소 과금이 시작된다. 런북은 저장소 위에서 Copilot을 쓰는 환경을 전제로 썼으므로 그대로 따라 하면 안 된다. HS AX팀은 STEP 12(Organization * Team 생성)를 건너뛴다.

이 원칙은 공동 관리자인 김준희 선임에게도 그대로 전한다.

3EMU * Entra ID * SAML SSO * SCIM 개념 정리

진행 이승희 (Microsoft)

이승희는 개념을 먼저 잡아야 이후 단계가 보이고 업무혁신팀 * GitHub와도 말이 통한다며 용어를 하나씩 풀었다. 클릭만 따라 하면 이후 관리와 소통이 막힌다는 것이다.

용어세션에서 정리한 뜻
EMU (Enterprise Managed Users)회사가 계정을 관리하는 GitHub 엔터프라이즈다. 개인이 회사 소스를 밖으로 가져가지 못하게 묶는다. 회사가 GitHub를 쓰려면 이 EMU부터 만든다.
Entra ID인증(authentication)과 권한 부여(authorization)를 맡는 Microsoft의 클라우드 인증 인프라다. 온프레미스에서는 Active Directory가 같은 일을 한다. LG전자 임직원은 M365를 쓰려고 이미 Entra ID 위에서 일하고 EMU도 Entra ID를 바탕으로 만든다.
SAML SSO (Task 1)SAML 프로토콜로 한 번 인증하면 GitHub Copilot에 따로 로그인하지 않고 들어간다. Teams와 메일에 바로 들어가는 것과 같은 원리다.
SCIM 프로비저닝 (Task 2)Entra ID에 있는 사용자 계정을 GitHub에 자동으로 만들어 준다. 같은 사람을 GitHub에 손으로 다시 만들지 않는다.
숏코드 (shortcode)프로비저닝된 사용자 이름에서 언더스코어 뒤에 붙는 문자열이다. 예: monalisa_lghsax의 lghsax
업무혁신팀의 Entra 설정 권한

SSO와 SCIM 프로비저닝은 모두 Entra ID에서 설정한다. HS AX팀에는 Entra 권한이 없으므로 본사 업무혁신팀에 필요한 정보를 넘기고 설정을 요청한다. 그래서 업무혁신팀과 최소 두 번 주고받는다.

4사용량 기반 과금(UBB) 전환과 사용량 관리

진행 이승희 (Microsoft)

이승희가 런북 부록의 Copilot 과금 항목을 열어 과금 방식이 바뀐 점을 짚었다. 몇 달 전까지는 사용자 한 명당 월 정액을 내면 마음껏 썼다.

지금은 기본 제공량까지만 쓰고 그다음부터는 쓴 만큼 낸다. 이 방식이 UBB(Usage Based Billing)다. 런북도 2026년 6월 1일부터 GitHub Copilot이 사용량 기반(AI Credit) 과금으로 바뀌었다고 적었다.

관리자가 사용량을 직접 관리해야 하므로 이승희는 런북 부록에 링크한 UBB 요금제 전환 온디맨드 영상과 발표 자료를 꼭 보라고 당부했다. 초과 사용을 막는 방법은 Q&A에 있다.

6STEP 2 * 3 셋업 어드민 암호와 SCIM 토큰(PAT) 발급

진행 이승희 (Microsoft) | 화면 공유 홍진섭 책임 (LGE HS AX추진팀)

GitHub가 보낸 메일 2통 가운데 Set your password 메일을 같은 시크릿 창의 Gmail 탭에서 열고 녹색 버튼을 눌렀다. 홍진섭 책임이 셋업 어드민 lghsax_admin의 암호를 정했다. GitHub는 15자 이상이거나 숫자와 소문자를 포함한 8자 이상을 요구한다.

암호를 정하고 들어가면 Welcome, lghsax_admin 화면에 남은 설정 3가지가 나온다. Generate SCIM token/ Enable single sign-on/ Configure provisioning이다.

SCIM 토큰은 Entra ID가 GitHub EMU에 접속할 때 쓰는 자격 증명이다. 셋업 어드민으로 로그인한 상태에서 Generate SCIM token을 누르면 Personal access token(classic) 화면이 열린다.

  • Note에 SCIM provisioning을 적는다.
  • Expiration은 No expiration으로 둔다.
  • Scope는 scim:enterprise 하나만 고른다.
  • Generate token을 누르고 토큰을 바로 복사한다. 이 화면을 벗어나면 토큰을 다시 볼 수 없다.

첫 화면으로 돌아가면 Generate SCIM token 항목에 완료 표시가 붙는다. 다음 항목인 SSO와 프로비저닝(Task 1 * 2)은 Entra 쪽 작업이다. 엔터프라이즈 첫 화면은 github.com/enterprises/lghsax로 열거나 우상단 프로필 메뉴의 Enterprise로 연다.

8STEP 5 이후 Entra 작업의 업무혁신팀 요청 방식

진행 이승희 (Microsoft)

런북 STEP 5(Entra EMU 앱 추가)부터는 작업자가 Entra Admin, 곧 본사 업무혁신팀이다. HS AX팀은 자기 몫을 끝냈고 이제 업무혁신팀 차례라는 점을 요청 메일에 분명히 적는다.

  1. 런북 링크를 넣고 STEP 5부터 진행해 달라고 적는다.
  2. STEP 3에서 만든 토큰을 'Personal Access Token(PAT)'이라는 이름과 함께 넣는다. 업무혁신팀이 PAT가 무엇인지 되물을 수 있어서다.
  3. 참조에 이승희(sunyi@microsoft.com)를 넣는다.

받는 사람은 업무혁신 기획인프라팀 윤지용 책임이름 표기 확인 필요이다. 정혜란 책임이 미리 연락해 두어 내용은 알고 있으니 HS AX팀은 세션이 끝나는 대로 메일을 보내기로 했다.

이승희는 업무혁신팀이 모르는 부분도 LG 안에서 R&R에 따라 업무혁신팀이 풀어야 한다고 선을 그었다. Microsoft가 LG 내부 절차를 대신 풀어 주는 구조는 정상 절차가 아니라는 것이다.
