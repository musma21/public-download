How to map a domain name to your M365 tenant

Adding and verifying a custom domain when DNS is hosted at Cloudflare

A domain can be verified in only one Microsoft 365 tenant at a time. Get the two access prerequisites and the previous-tenant check right up front, and the rest of the flow — add, verify, publish DNS records — takes about fifteen minutes plus propagation.

·The whole flow in four moves

Everything below is one of these four steps. If a step fails, the cause is almost always in the step before it — work backwards rather than retrying the same screen.

0Two levels of access — and one blocking pre-check

You need both levels of access below. Missing either one blocks the verification step, not just the final DNS publish.

  • Global Administrator in the Microsoft 365 admin center for the target tenant.
  • Domain management rights at Cloudflare.com — the account that owns the DNS zone.
⚠ Read this first

If the domain name you want to use is already in use by another Microsoft 365 tenant, you must sign in to that previous tenant as an administrator and remove the domain there before starting the steps below. Skipping this makes the add-domain step fail with an "already in use" error.

Pre-flight check

  • Confirm the nameservers actually point to Cloudflare — Cloudflare must be authoritative for DNS, not merely the registrar.
  • Note any existing MX, SPF or CNAME records; Microsoft 365 will ask for records that can collide with a current mail provider.
  • Decide between the guided flow (Microsoft writes the records) and manual entry. This note uses the guided flow.

1Add the apex domain, not a subdomain

Sign in to the Microsoft 365 admin center, then open Settings → Domains and select Add domain. Enter the domain exactly as registered — the apex name, for example contoso.com, without www. — and continue.

If it fails here

An "already in use" message means the domain is still attached to another tenant. Remove it there first, then retry — no amount of DNS work at Cloudflare will clear this.

2Let Microsoft write the verification record for you

Microsoft 365 detects the DNS host and offers to verify by connecting directly to it. When Cloudflare is detected, choose the sign-in option and press Verify — you are redirected to Cloudflare to authenticate and to authorise Microsoft to create the verification record for you.

Manual alternative

If you would rather not connect the accounts, add the verification record yourself in the Cloudflare DNS tab, wait a minute or two, then return to the admin center and press Verify again.

⚠ Cloudflare-specific

Set every Microsoft 365 record to DNS only (grey cloud). Records left proxied (orange cloud) break mail flow and service discovery, because Cloudflare answers with its own IP addresses instead of Microsoft's.

4The domain is not done until it reads Healthy

  1. Return to the admin center, complete the wizard and let Microsoft run its DNS check — records may take a few minutes to propagate.
  2. Confirm the domain now reads Healthy under Settings → Domains.
  3. Assign the new domain to a user or group as the primary email address, then send a test message in and out.
  4. If you migrated from another mail provider, remove the old MX and SPF entries so mail is not split between two systems.

5Making it Default does not move existing users

Once the domain is Healthy, decide whether it should become the tenant's Default domain — the one proposed automatically for newly created accounts. Both the new domain and the original *.onmicrosoft.com domain stay listed and both should read Healthy.

⚠ Easy to miss

Setting the new domain as Default changes nothing for people who already have accounts — their sign-in addresses stay on the old domain. Existing users must be switched one by one.

Switching an existing user

Go to Users → Active users, open the person, and use Manage username. Pick the new domain from the drop-down beside the username field and save.

Tell them first

The pane warns that you are about to change the user's sign-in information. Changing the username changes how they sign in and where mail addressed to the old address is routed, so notify the person before you save — and keep the old address as an alias if mail is still arriving on it.
