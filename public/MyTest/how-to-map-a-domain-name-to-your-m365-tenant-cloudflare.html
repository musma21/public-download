How to map a domain name to your M365 tenant (Cloudflare)

A step-by-step guide to adding and verifying a custom domain in the Microsoft 365 admin center when DNS is hosted at Cloudflare.

Audience: Tenant administrators Time required: ~15 minutes (plus DNS propagation)

Before you start

You need both of the following levels of access. Without either one, the verification step cannot be completed.

  • Global Administrator in the Microsoft 365 admin center for the target tenant.
  • Domain management rights for the domain at Cloudflare.com (the account where the zone lives).
⚠️ Important — if the domain name you want to use is already in use by another Microsoft 365 tenant, you must first sign in to that previous tenant as an administrator and remove the domain there. A domain can only be verified in one tenant at a time; skipping this step will cause the add-domain step below to fail.

Quick pre-flight check

  • Confirm the domain's nameservers actually point to Cloudflare (Cloudflare must be authoritative for DNS, not just a registrar).
  • Note any existing MX, SPF, or CNAME records — Microsoft 365 will ask to add records that may conflict with an existing mail provider.
  • Decide whether you want Microsoft to manage records for you or to add them manually (this guide uses the guided/verify flow).

1Add the domain in the Microsoft 365 admin center

Sign in to the Microsoft 365 admin center, then go to Settings → Domains and select Add domain. Enter the domain name exactly as registered (for example contoso.com, without www.) and continue.

If the portal reports that the domain is already in use, return to the warning above: the domain is still attached to another tenant and must be removed there first.

2Verify ownership through Cloudflare

Microsoft 365 offers to verify the domain by connecting directly to your DNS host. When Cloudflare is detected, choose the sign-in option and press Verify — you will be redirected to Cloudflare to authenticate and to authorise Microsoft to create the verification record.

If you prefer to verify manually

Instead of connecting the accounts, you can add the verification record yourself in the Cloudflare DNS tab:

TypeNameValueProxy status
TXT@MS=msXXXXXXXX (value shown in the portal)DNS only

Save the record, wait a minute or two, then return to the admin center and select Verify again.

3Add the Microsoft 365 service records

Once ownership is confirmed, the portal lists the DNS records required for the services you use. Add them in Cloudflare's DNS tab. The typical set is:

PurposeTypeHost / NamePoints to
Exchange Online mail flowMX@<domain-key>.mail.protection.outlook.com (priority 0)
AutodiscoverCNAMEautodiscoverautodiscover.outlook.com
SPF (anti-spam)TXT@v=spf1 include:spf.protection.outlook.com -all

Cloudflare tip — set the proxy status of every Microsoft 365 record to DNS only (grey cloud). Records left in proxied mode (orange cloud) break mail flow and service discovery, because Cloudflare returns its own IP addresses instead of Microsoft's.

4Finish and validate

  1. Back in the admin center, complete the wizard and let Microsoft run its DNS check. Records may take a few minutes to propagate.
  2. Confirm the domain now shows as Healthy under Settings → Domains.
  3. Assign the new domain to a user or group as the primary email address, then send a test message in and out.
  4. If you migrated from another mail provider, remove the old MX and SPF entries so mail is not split between systems.

Troubleshooting

  • "Domain is already in use" — remove it from the previous tenant first, then retry.
  • Verification keeps failing — check that the TXT record is on the root (@) and set to DNS only; use a public DNS lookup to confirm it is visible externally.
  • Mail is not delivered — an orange-cloud (proxied) MX record or a leftover MX from the old provider is the usual cause.
  • Teams sign-in issues — confirm the SRV records were saved with the correct port and priority values.
